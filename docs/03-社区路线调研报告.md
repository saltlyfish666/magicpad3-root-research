## 2. 同代内核 6.1.157 的实战研究（最贴近你机器）

| 项 | 内容 |
|---|---|
| 仓库 | **knowlily/cve-2026-43499-honor** `https://github.com/knowlily/cve-2026-43499-honor` |
| 设备 | Honor Magic6 Pro (BVL-AN16)，SM8650，**内核 6.1.157-android14-11-g7d3922fade43，MagicOS 10.0.0.170** ← 与你的机器**同一代内核、同一固件版本** |
| 结论 | 已确认 6.1.157 上漏洞**未修**（`remove_waiter` 无修复签名），并拿到**同机同内核的第三方成功样本** |
| 成功样本日志 | `read_ok=1 write_ok=1 rw64=1/1 uid=2000->0` → `kernelsu 192512 2 - Live` |

### ⚠️ 最有价值的一条：他们的"第三方成功样本"就是你这套 kit

报告原文对照表：

| | 该仓（自上游移植） | 第三方包 `ksu_root_bvl-an16` |
|---|---|---|
| 出身 | 上游多机型树 | **荣耀 CGA-W00(MagicPad3) 成品包（GhostLock-H80GT/ksu 血统）** |
| 载体 | fmps ioctl（必须 app 域） | **pselect（shell 域 uid 2000 直接跑）** |
| 关键差别 | 无 res-encode | **`SLIDE_PSELECT_RES_ENCODE=1`** |

也就是说：**你手上这套 `ksu-cga-release-1.5.5` 就是他们验证过能在 6.1.157 上成功的那个包**，命中率低是手法固有的（他们实测窗口只有 ~40-50%）。

### 他们踩出来的 3 个真 bug（工程价值极高）

1. **`ASHMEM_MISC_FOPS_OFF` 一直是错的** —— 荣耀符号叫 `ashmem_miscs`（复数），生成脚本查单数失败后**静默 fallback** 成 `ashmem_fops`，导致写原语打错地方。
   > **判据：`ASHMEM_MISC_FOPS_OFF == ASHMEM_FOPS_OFF` ⇒ 一定是错的。**
   这与你日志里 `cfi … verified=0 dirty=0` 的症状高度吻合，**值得拿你的 kit 核一下这两个常量是否相等**。
2. **缺 `res-encode`** —— 荣耀 6.1 把 `do_futex` 内联，`PSELECT_WAITER_WORD_SHIFT=11`，旧代码直接 `return 0` 静默丢弃 `g>=15` 的 word，导致 `waiter->lock` 恒为 0 → `_raw_spin_trylock(NULL)` → panic。**"容量不够"是症状不是结论**。
3. **`shift_candidates[] = {1}`**（三星遗留值）覆盖了推导出的 11，把伪造 waiter 放偏 0x50 字节，永远对不上。

### 他们指出的第三方包 3 处待修

| 位置 | 问题 | 修法 |
|---|---|---|
| `exploit_bvl/target.h` | `APP_FOPS_SINGLE_SHOT 1` | **→ 0（成功报告列为关键修复之一）** |
| `exploit_bvl/target.h` | `MM_STRUCT_SZ 0x3c0` | → `0x400` |
| `get_root_oneclick.bat` | `if not exist "%ADB%"` 恒真 | 候选表解析 adb 路径 |

> `APP_FOPS_SINGLE_SHOT` 这条对你很有意义：你的日志是
> `app fops slide attempt=1/8` → `APP_FOPS_SINGLE_SHOT attempt=1 done … stopping`
> 即**有 8 次机会却只打了 1 次就停手**。若能改成 0，单 boot 的尝试次数直接 ×8。

## 4. 目前最值得投入的替代路线：DFRoot (DirtyFrag / CVE-2026-43284)

| 项 | 内容 |
|---|---|
| 仓库 | **diabl0w/DFRoot** ★287 `https://github.com/diabl0w/DFRoot`（另有 `a2333c/DFRoot` 三星适配版 ★6） |
| 原理 | **页缓存写原语**：内核把 AES-CBC ESP 包直接解密进 `splice()` 打开文件的 page cache，用 `IV = AES_ECB_DEC(key, 现内容) ⊕ 期望内容` 实现**任意 16 字节对齐块覆写，无需写权限、无 COW**。把 shellcode 打进 `libc++.so` 的页缓存 → init 域触发 → `insmod` 加载自定义内核模块 |
| 优势 | ①**确定性、非竞态**（"there is no race to win"）②**不需要解锁 BL** ③**不需要 Shizuku**（"regain root without WiFi"）④**支持开机自动获取 root** ⑤模块可管理 |
| 风险 | FAQ 明确：内核太新 / 厂商回移了官方缓解 / **"Accidental mitigation（kernel 6.1 上常见）"** → 会直接报"你的设备不受影响"。**你的机器正好是 6.1.157，属高危区间** |

### ❌ 实测结果（2026-10-14 00:10-00:40）：**在本机跑不起来，已放弃该路线**

DFRoot 4.1（`df.root`，80KB）安装成功、权限齐全、界面正常，但 **`Select a SU Manager` 下拉列表恒为空 → `LAUNCH ROOT` 永久灰色禁用**，用户手动触摸同样无反应。已逐一排除：

| 假设 | 验证结果 |
|---|---|
| 需要 KernelSU-Next 才认 | ❌ 装好完整 v3.4.1（`com.rifsxd.ksunext`，包体 15,132,143 字节校验一致）后依然空 |
| 需要联网拉列表 | ❌ 平板 ping `github.com` / `raw.githubusercontent.com` / `objects.githubusercontent.com` 全通 |
| `QUERY_ALL_PACKAGES` 没授予 | ❌ `dumpsys package df.root` 显示 `granted=true` |
| 有硬编码包名白名单 | ❌ 反编译 `classes.dex` + `libdfroot.so` + `libbootstrap.so`，**完全没有 SU 包名字符串**，是通用扫描 |
| `libksud.so` 路径不可达 | ❌ `/data/app` → `~~hash==` → pkg → `lib` → `arm64` 全链可 traverse（0711/0755 权限正确） |
| 偏好文件命名不一致（App 写 `df.root_preferences.xml`，代码读 `shared_prefs/dfroot.xml`） | ❌ 用 root 手写 `dfroot.xml`（`su_manager=me.weishu.kernelsu`，uid/权限/SELinux 上下文 `c8,c257,c512,c768` 全对齐）后重启，**依然空** |
| 国产 ROM 的 `GET_INSTALLED_APPS` 拦截 | ❌ 本机**根本没有这个 op**（`Error: Unknown operation string: GET_INSTALLED_APPS`） |

**结论**：DFRoot 4.1 与 MagicOS 10 / Android 16（CGL-W00）不兼容（作者 README 只列了三星 S22/S26/ZFold8 的实测）。如实测 DirtyFrag 是否被缓解，只能去 XDA 原帖问作者 `diabl0w`。

> ⚠️ 附带踩到的坑：`appops query-op <OP>` 这种**遍历全机的重查询会把 system_server 搞崩并重启**，连带 adbd 断链（表现为 `adb offline` 几分钟，但 uptime/boot_id 不变、root 不丢）。**别用 `appops query-op`。**

## 6. 关于"拿到 root 也不稳"的权威解释

`hui191/cve-2026-43499-aak-an00` 把根因写得很清楚（这段也解释了本机 23:44 那次 panic）：

> exploit 的写原语会把**伪造的 `rt_mutex_waiter` 挂进真实的 futex PI 链**，而这个 waiter 的载体是**会被后续系统调用复用的内核栈 / 喷射页**。于是从 root 落地那一刻起，任何一次**系统级调度或优先级变动**都可能踩到它，直接内核 panic 重启。
> **这不是 bug，是这套利用手法的固有代价。**

**实践含义**：FlashLight 式 root 落地后应**尽量少折腾**（别装一堆模块、别频繁调调度/优先级类操作），否则 PI 链残留随时可能引爆。
