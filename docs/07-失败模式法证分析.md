- 设备：Honor MagicPad3（CGL-W00，MagicOS 10.0.0.170，内核 `6.1.157-android14-11-g19a495a97bff`）
- 语料：`.workbuddy\hitsample\`（hit / hit2 黄金集）、`.workbuddy\logstudy\`（miss 黄金集）、`D:\file\文档\workbuddy\2026-10-13-11-14-12\auto_root_logs\`（43 份逐发 dcshot：41 miss + 2 jam）

## 0. 总结论（先看这条）

**没有"开火前可观测、hit 与 miss 完全不重叠"的信号。无事前指纹，与上一任结论一致。**

- 对 3 份 HIT + 41 份 MISS 的 dc_ksu.log 做 **PRE（首条 `p0 physical write` 之前）key=value 全量分离度扫描**，结果一行：`PRE 完全不重叠: (无)`。
- 二分发生在 `p0 physical write status=0 ok=1` **之后**的 CFI misc_fops 恢复那一步，而 `p0 physical write` 双侧都是 `ok=1`，即写入动作本身已经成功，成败由随后的 configfs restore 决定。
- 唯一双侧不重叠的字段集全部位于 POST 段 = 结局本身（`done/root/read_ok/write_ok/step/verified/uid`），不构成事前信号。

### 最接近判别的 top3（及其重叠情况）

## 1. cga43499_walk_state：68 字节逐字节 diff

三份文件 `hitsample\hit_cga43499_walk_state`、`hitsample\hit2_cga43499_walk_state`、`logstudy\cga43499_walk_state` **字节完全一致（sha1 同为 `e03152acbd92…`，长度均 68）**，全文：

```
spin_done=1 sched_ok=4 write_window=1 consume_calls=4 enter_sched=4
```

字段解释与判别力：

| 字段 | 值 | 含义 | 判别力 |
|------|----|------|--------|
| `spin_done` | 1 | sigreturn 自旋阶段完成 | 无（hit=miss=1） |
| `sched_ok` | 4 | 调度相关四步全部 ok | 无（双侧同值，但见 §5：cp.log 里 =4 只是必要条件） |
| `write_window` | 1 | 写窗口已打开 | 无（双侧同值） |
| `consume_calls` | 4 | consumer 触发次数 | 无（双侧同值） |
| `enter_sched` | 4 | 进入调度路径次数 | 无（双侧同值） |

**逐字节 diff 结果：零差异。** 该文件是"该进程走到 write_window 的快照"，hit 与 miss 都走到这一步，故不携带任何结局信息。注意 dcshot/逐发层面 `write_window=0`、`consume_calls=2`、`sched_ok=3` 只出现在 MISS（见 §5），说明**文件级快照与逐发行级分布口径不同**——文件快照的取值恒为"成功形态"，但失败时该文件同样被写成这个值，因此仍无事前判别力。

## 2. cfi_state.log：结构/值 diff，是否"写之前就注定 restore 失败"

### 2.1 结构

单行固定格式，字段全集：

```
lseek pre_ret=-1 pre_errno=0 new_ret=-1 new_errno=0 replaced=0 misc_fops=ffffffda09d3c340 fake_fops=ffffff8874851000
```
（`hitsample\hit_cfi_state.log:1`）

- `pre_ret/pre_errno`、`new_ret/new_errno`：lseek 对 pre/post fd 的返回与 errno
- `replaced=0`：是否完成替换
- `misc_fops`：目标 misc_fops 地址（低 12 位恒 `0xc340` = `kaslr_base+0x253c340`，高位随 boot 变化 ⇒ **每行 ≈ 一次 boot**）
- `fake_fops`：伪造 fops 地址

### 2.2 值 diff

| 文件 | 行数 | 字段值组合 |
|------|------|-----------|
| `.workbuddy\devlog\cfi_state.log` | 52 | 全部 `-1/0/-1/0/0` |
| `logstudy\cfi_state.log` | 99 | 全部 `-1/0/-1/0/0` |
| `hitsample\hit_cfi_state.log` | 116 | 全部 `-1/0/-1/0/0` |
| `hitsample\hit2_cfi_state.log` | 129 | 全部 `-1/0/-1/0/0` |

- **嵌套关系（严格字节前缀）**：`devlog(52) ⊂ logstudy(99) ⊂ hit_cfi(116) ⊂ hit2_cfi(129)`，公共行 0 mismatch ⇒ 四份是**同一份累积追加文件在不同时刻的抓取**，行数差异只是抓取时间差，不是结局差异。
- 因此 `cfi_state.log` 里**既没有 HIT 独有行，也没有 MISS 独有行**：`replaced` 恒 0，`pre_errno/new_errno` 恒 0，无任何方差。

### 2.3 回答"写之前是否注定 restore 会失败"

**否。** `cfi_state.log` 记录的是 `CFI_SKIP_VERIFY=1` 路径下的 lseek oracle（`ret=-1 errno=0`），它在 hit 与 miss 中完全相同，**不存在能预言 `configfs restore FAILED errno=22` 的字段**。真正分岔出现在 dc_ksu.log 的下一行（POST 段）：

- HIT：`[*] cfi restoring misc_fops target=ffffffe0b253c340 value=ffffffe0b1274ae8` → `[*] cfi misc_fops readback ret=8 val=ffffffe0b1274ae8 (restored)`
- MISS：`[*] cfi restoring misc_fops target=ffffffe6dbf3c340 value=ffffffe6dac74ae8` → `[-] cfi misc_fops restore via configfs FAILED ret=-1 errno=22 - will retry via pipe physrw after privilege escalation`

两侧行前的状态（`cfi lseek probe SKIPPED (geo119)`、`cfi fd-diff SKIPPED (CFI_SKIP_VERIFY=1)`、`p0 physical write status=0 ok=1`、`preopen configfs selfcheck ret=0 ... errno=0`）**完全一致**，分岔点在写入之后的 readback/restore 阶段，属"写时才知道"，非"写前可观测"。

## 6. poison_hunt / poison_trap / ksu_load / loadko_result：因果顺序

产生点（全语料 grep 仅此一处）：

- `honor_kit\assets__kit__ksu_loader.sh:130` `rm -f $RD/poison_hunt.log` → `:131-141` 跑 `poison_hunt` 写 `poison_hunt.log`
- `:149` `rm -f $RD/file_hunt.log $RD/ph_all.log` → `:169` `setsid ... poison_hunt --all-procs >> $RD/ph_all.log`
- `:176` `rm -f $RD/poison_trap.log` → `:179` `setsid sh $RD/poison_trap.sh`
- `ksu_loader.sh` 只在**提权成功后的 rooted 子进程**执行；miss 的 `dc_ksu.log` 末尾是 `cat: .../ksu_load.log: No such file or directory` ⇒ **该发 ksu_loader 未运行**。

判定：**ksu_load.log / loadko_result.log / poison_hunt.log / poison_trap.log / ph_all.log 全部是命中后（post-root）产物**，时序上位于 `pipe physrw done=1 root=1` 之后，**不可能成为事前信号**。

证据：
- `hitsample\hit_loadko_result.log`：`[*] read /data/local/tmp/ksu/kernelsu.ko (5540360 bytes)` … `[+] module loaded OK!`；`logstudy\` 无 `loadko_result.log`（hit-only）。
- `hitsample\hit_ksu_load.log` / `hit2_ksu_load.log` 存在；`logstudy\` 无 `ksu_load.log`。
- `hit_poison_hunt.log`：`done - processes=5 pages=0 poison_words=0 scrubbed=0`（5 个 cve pid）；`logstudy\poison_hunt.log`：`done - processes=4 pages=0 poison_words=0 scrubbed=0`（4 个 cve pid）——**两侧都 `pages=0 poison_words=0`，无差异**。
- `hit_poison_trap.log` / `logstudy\poison_trap.log` 均 22 字节：`trap start uptime=300` vs `trap start uptime=131`（仅 uptime 不同）。
- ⚠️ 疑点已注明：`logstudy`（miss）也带 `poison_hunt/poison_trap/ph_all`，且 `ph_all.log` mtime=20:02:55（紧跟该 miss 的 dc_ksu 20:02:39）。按脚本谱系这些文件只能由 ksu_loader 生成，而该 miss 的 ksu_loader 并未运行 ⇒ **logstudy 目录是多次拉取/手工合并的混合档**（`memory\2026-10-14.md:51` 记录"失败样本日志已存 `.workbuddy/logstudy/`"），其 poison_* 的归属存疑，**无论归属如何都不影响结论：这些文件双侧值域相同（pages=0）**。

## 7. 明确回答

### 有没有"开火前可观测、hit 与 miss 完全不重叠"的信号？

**没有。无事前指纹，与上一任结论一致。**

依据：
1. PRE 段 key=value 全量扫描（3 HIT vs 41 MISS + 43 dcshot）：`完全不重叠: (无)`。
2. `cga43499_walk_state` 三份字节全同（sha1 `e03152acbd92…`）。
3. `cfi_state.log` 四份是前缀嵌套、100% 同值组合 `-1/0/-1/0/0`，无方差。
4. `cp.log` 是跨 boot 累积档且三份前缀嵌套；geom 块除 `target`/`pc`（已知恒定公式）外全部字段恒定或双侧同值。
5. `ph_all.log` 双侧都有 poison 页（miss 的 32 页全在 launcher/hiboard 等无关进程）；`aff_diag.log` miss 侧**缺失**，且 hit 内部 `Cpus_allowed_list` 3 与 0-7 都出现过。
6. `poison_* / ksu_load / loadko_result` 均为 post-root 产物，时序上不可用作事前信号。
7. 唯一双侧不重叠的字段全在 POST 段（`step/verified/done/root/read_ok/write_ok/uid`），等于结局本身。

### Top3 最接近判别（全部有重叠）

1. **`write_window`**：HIT `{1}` vs MISS `{0,1}` — 重叠于 `1`；`0` 仅 MISS（负向）。
2. **`consume_calls`**：HIT `{4}` vs MISS `{2,4}` — 重叠于 `4`；`2` 仅 MISS（负向）。
3. **`sched_ok`**：HIT `{1,4}` vs MISS `{1,3,4}` — 重叠于 `1,4`；cp.log 层 `sched_ok=4` 是 cfi-SUCCESS 的必要非充分条件（4 成功 vs 101 失败同为 4）。

> 建议（若要继续找）：分岔点在 `p0 physical write ok=1` 与 `cfi restore readback` 之间，属**写入时/写入后**微窗口；现有日志在该窗口内没有任何更细的状态埋点。若要获得事前信号，需在 `cfi restoring` 前新增探针（如 configfs 可写性预检、misc_fops 页 CFI 校验状态），而非继续挖现有日志。
